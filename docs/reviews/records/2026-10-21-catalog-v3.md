## Findings

- **Descriptor sections are optional because most models have none.** A widget
  has no runtime ports, parent roles, or guidance, and serializing four empty
  sections for 29 widgets would be noise a client has to filter. Each section
  is skipped when empty; `ports` empty means "no static ports", not "cannot
  connect", because protocol ports are configuration-derived and arrive through
  `describe`. The contract version bump is what makes a missing section safe:
  an older client rejects v3 instead of rendering a descriptor it only partly
  understands.
- **The catalog derives every new fact from the owning registry.** Driver
  ports come from `port_descriptors(&Value::Null)` (the same static face
  `DriverRegistry::manifests` uses), capabilities from the static mask,
  guidance from `NodeDriver::guidance`, and `parent_roles` from the inverse of
  every driver's `ChildPolicy` — a role is reachable if some registered driver
  allows it, so adding a driver updates the catalog without a second table.
  The simulation driver is excluded from that inverse because it is a child
  semantic, not a creatable parent.
- **Guidance carries the English fallback, not an invented key.** The
  descriptor has `summary_key` / `when_to_use_key` / `docs_key` fields, but the
  registry only owns prose. Filling a key before the frontend ships the
  resource would turn every guidance lookup into a dead reference, which is
  worse than rendering the fallback; keys stay absent until the client
  resources exist, following the `ModelDisplay::label_key` rule.
- **A protocol publishes no static ports.** Channel protocols derive ports from
  `channels`, and `custom` derives them from decode blocks, so a catalog entry
  cannot state them without an instance. The descriptor says so by leaving
  `ports` empty and the invariant is pinned by a test rather than a comment.
- **Validation returns issues, not a failed command.** The form-subset
  validator walks `type`, `properties`, `required`, `items`, `minimum`,
  `maximum`, `minLength`, and `enum`, and reports `$`, `$.field`, and
  `$.field[0]` paths. Driver-level semantic errors land on the root path, so
  every issue has a path and the caller renders `code`, `path`, and `severity`
  once. An unknown driver is a single issue instead of a cascade, and a
  configuration problem never fails the RPC: only an undecodable request does.
  The command keeps its name and payload argument; its response gained the
  issue list. No frontend caller consumed the old return value, and the API
  wrapper was updated in the same change.
- **The validator implements the documented subset and stops there.** Unknown
  schema keywords are skipped instead of guessed; `pattern`,
  `additionalProperties`, `oneOf`, and `$ref` remain unsupported and are
  enforced by neither side. The schema shape stays the contract the form
  renderer already consumes.
- **Preview does not open hardware.** The target contract said "opens a
  transient source"; opening a device from a preview would mutate the device
  lifecycle and race the runtime that already owns the node. The implemented
  window is a transient broadcast subscription on an already-open byte source:
  at most 4 KiB or 500 ms, released before returning, with no background task.
  Without a `nodeId` it parses supplied input. Both paths use
  `schema::compile_protocol`, the same assembly the graph uses, so preview sees
  what the runtime will see; the engine instance is private to the call.
- **Preview is bounded in three places.** Input bytes, capture bytes, and
  returned frames are capped; the response carries `truncated` so a caller can
  tell a complete window from a cut one. Trailing bytes that do not form a
  frame are reported, not silently dropped. Logic-decoded output is not
  projected into the frame table; it is reported as an informational issue
  instead of being presented as zero frames.
- **Discovery confidence states what the adapter actually verified.**
  `serial` reports 1.0 (the OS device is a serial port and the `serial` driver
  opens it), candleLight reports 1.0 (enumeration filters the candleLight
  VID/PID), and Modbus RTU reports 0.4 (the port exists, no slave was
  verified). The field is a ranking hint, not a promise. `DiscoveredEndpoint`
  lost `Eq` because `f32` cannot implement it; no consumer required `Eq`.
- **One wire type was already an IPC contract but not exported.**
  `CanFrame` had a hand-written wire shape and a hand-written frontend mirror.
  Preview needs it in generated TypeScript, so `CanFrame` and `CanDirection`
  now derive `ts-rs::TS` from fields that the custom serde does not rename or
  reshape. `DataFrame` and `protocol::InputFormat` are exported for the same
  response. The lower-layer external dependency baseline gained exactly those
  `ts-rs` edges; the reviewed dependency count rose by two edges and no
  adapter SDK was added.

## Follow-ups

- **SLCAN discovery still suggests `serial`.** `CanTransportBackend::discover`
  delegates SLCAN to the serial backend, whose results carry
  `suggestedDriver: serial`; the factory then rewrites `adapterId` to `slcan`.
  The identified hardware really is a serial port, but a UI that auto-picks on
  `suggestedDriver` would create a serial node. Decide whether the SLCAN face
  should rewrite the recommendation or keep it.
- **The hand-written `client/src/types/can.ts` duplicates the new generated
  `CanFrame`, and `client/src/types/frameDecoder.ts` duplicates `InputFormat`.**
  Replace both with the generated types when those display paths migrate; two
  contracts for one wire shape will drift.
- **Logic-decoded preview output is not projected.** The frame table handles
  data and CAN frames only. A logic inspector needs its own sample/event
  projection, or preview will keep reporting an informational issue for
  `logicDecode`.
- **Guidance translation keys are absent.** The descriptors expose the fields;
  the client resource files and key names belong to the client rendering
  workstream.
- **The form-subset validator does not cover the whole schema vocabulary.**
  `pattern`, `additionalProperties`, and `oneOf` are skipped by design; a
  configuration that violates them is accepted by the backend and may be
  rejected by a stricter client. Either keep the schemas inside the subset or
  extend the validator deliberately.
- **Driver guidance is English prose owned by the driver crates.** Localization
  is a frontend resource concern; no key naming exists yet.
