# 动效空间化改造计划

本文件描述 `src/lib/motion/` 落地之后**尚未完成**的界面改造。
已完成的物理引擎与令牌层见 `motion-tokens.md`；本文只讲接下来做什么、为什么。

## 判断标准

一条动效是否合格，用三个问题检验：

1. **它从哪里来？** 观众能不能从位移方向和缩放原点推断出这个表面归属哪里。
   不能，就是纯装饰。
2. **它有多远？** 幅度与实际路程是否匹配。移动 600px 与移动 40px 用同一组
   参数，其中一个必然读错。
3. **它凭什么这样动？** 能否用"一个被弹簧约束的物体"解释。
   解释不了的（尤其是匀速、匀加速、线性淡入）都是待改项。

不满足以上任意一条的现有动效，都进入下面的清单。

## 已具备的能力

改造时直接使用，不需要重新实现：

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 物理弹簧 | `motionSpring(family, phase)` | 闭合解，`duration` 是解出来的 |
| 距离感知时长 | `motionSpringFor(family, phase, px)` | 按实测路程拉伸 |
| 进场/离场几何 | `MotionPresence` 的 `origin` / `travel` / `scale` | 传真实锚点 |
| 进场/离场不同令牌 | `--ease-<家族>-out` | 离场恒为临界阻尼 |
| 错峰 | 尚未封装 | 需要新增，见下 |
| 共享元素与重排 | 尚未封装 | 需要新增，见下 |
| 合成器图层预算 | `promote()` / `release()` | 引用计数，用完即卸 |

## 待改造界面

按"违反上述判断标准的严重程度"排序，不按实现难度排序。

### Tab 滑动指示器 —— 每帧一次布局

`src/components/ui/SlidingPill.tsx` 过渡 `left/top/width/height`。
这四个属性每次变化都触发一次布局重算，与"动效只跑在合成器线程"的红线直接冲突。

改为：只写 `transform`（`translate` + `scale`），由 JS 在测量后一次性换算。
几何信息已经通过 ResizeObserver 拿到，改动局限在这一个组件。

### Dock 换边与面板迁移 —— 目前是瞬移

`src/App.tsx` 用 `key={...}` 强制重挂载 PanelGroup，面板在 left / right / bottom /
float 之间切换时直接跳到新位置，没有从旧位置飞过去的连续性。

改为：用 GSAP Flip（或等价的手写 FLIP）在提交新布局前后各测一次矩形，
让面板从旧矩形变形到新矩形。这也让"面板从它所属的 dock 边展开"成为可能 ——
`MotionPresence` 已经支持 `origin`，缺的只是锚点信息。

### 面板展开方向 —— 目前与所属边无关

停靠面板的入场位移是 CSS 里写死的 `translateX(±28px)`（`ai-panel.css`），
与它实际停靠在左还是右没有绑定关系。

改为：由 dock 边推导 `origin` 与位移方向，作为 prop 传入 `MotionPresence`，
删掉 `ai-panel.css` 里的方向性关键帧 —— JS 路径与非 JS 路径不再各播一次。

### 列表与时间线 —— 全部同时出现

控件调色板行、菜单项、AI 对话气泡与时间线节点都是同一帧一起出现。
十几行内容同时淡入时，观众读到的是"闪了一下"而不是"内容到齐了"。

改为：按索引错峰，每项延迟几毫秒。延迟上限需要封顶，否则长列表末尾会显得迟钝。
新增 `useStaggerEntrance()`，用现有的 `content` 家族令牌。

### 退场时的位移补偿 —— 兄弟节点跳变

列表行退出时直接消失，其余行瞬间上移填补空位。

改为：退场项在其余行重排前保持占位并同步位移（FLIP 的 classic 形式），
退场与让位同时进行。

### 拖拽释放 —— 无惯性

`src/lib/dockDrag.ts` 的幽灵元素松手后瞬时清除，只有一个 180ms 的放大淡出。

改为：把释放速度交给 `springVelocity()`，让幽灵带着松手时的动量落到落点。
速度来源是 pointermove 的最近若干帧位移，不需要新的采样循环。

### 节点编辑器

`@xyflow/react` 自带节点增删过渡，未统一到家族令牌下。优先级低于以上各项：
它本身的空间连续性已经由 React Flow 提供，改造主要是让时长与回弹与全app 一致。

### Widget 与图表

Widget 卡片布局重排（FRUIT 拖拽改序）目前是瞬时重排。图表数据更新本身不该有动画
（会误导读数），只有"数据源切换"才配转场。

## 执行顺序上的依赖

错峰与退场补偿共用同一套索引信息，先做错峰再做补偿。

拖拽惯性依赖 `springVelocity()`，该函数已经实现并有解析解验证，但没有调用方，
接入前不需要额外改动。

## 每项改造的完成标准

- 新增动效必须走 `motionSpring*()` 或家族令牌，不允许新写 `cubic-bezier(...)`
- 新增界面动效必须有对应的低动画退化路径，且退化路径只在
  `reduced-motion.css` 的清单里登记一次
- 每个改造配一条 Vitest，用断言空间关系（方向、距离、是否位移）而不是断言
  具体的毫秒数 —— 毫秒数会随调参变化，断言它必然在调参时失败
- `pnpm typecheck`、`pnpm lint:ci`、`pnpm test`、`pnpm build:web`、
  `pnpm test:e2e` 全绿，且 `pnpm dev:desktop` 实际点开确认
