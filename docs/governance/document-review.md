文档审查分两层：**机器门禁**（`pnpm check:docs`，CI 必过）与**人工评审**
（按 [checklist.md](../reviews/checklist.md) 逐项过）。机器管可判定项，人管判断题；
人工结论落成 [../reviews/records/](../reviews/records/) 下的一份记录。

## 触发条件

| 触发 | 动作 |
| --- | --- |
| 新增或删除 `docs/` 下的文档 | 必须入索引 + 走人工评审 |
| 修改治理文档、`NOTICE`、`CLA.md` 等法律/政策文件 | 必须走人工评审 |
| 许可证、版权、专利、对外表述口径变化 | 必须走人工评审，并同步 README 双语 License 段落 |
| 新增/升级/移除第三方依赖 | 更新 third-party 清单 + 走人工评审 |
| 发布形态、发布流水线、Dockerfile 变化 | 复核分发合规表 + 走人工评审 |
| 季度例行复核 | `pnpm check:docs -- --stale-days 180`，超阈值即判定治理文档过期 |

## 流程

1. **自检**。作者对照 [checklist.md](../reviews/checklist.md) 逐项确认，更新文档元数据
   的 `last-reviewed`。
2. **机器门禁**。`pnpm check:docs` 必须通过；本地可用 `pnpm check:all` 覆盖全部门禁。
3. **人工评审**。由非作者本人复核清单中的"事实一致性"与"许可证与知识产权"两组。
   单人项目由维护者对自身改动做一次显式的清单复核，并在记录中写明。
4. **留档**。在 `docs/reviews/records/` 新建 `YYYY-MM-DD-<范围>.md`，填写元数据与
   三段正文（范围 / 结论 / 遗留项），并在 [../reviews/README.md](../reviews/README.md)
   的索引表追加一行。
5. **合入**。门禁与记录都齐了才合入；不通过项按结论处理。

## 结论与处理

| 结论 | 含义 | 后续 |
| --- | --- | --- |
| 通过 | 无遗留问题 | 归档记录，更新元数据日期 |
| 有条件通过 | 有明确待办，不影响正确性 | 遗留项写明负责人与到期日；到期未清则在下次评审时升级 |
| 不通过 | 存在事实错误、越权表述或合规风险 | 不得合入；改正后重新评审 |

豁免：确需让某项不满足门禁时，在评审记录中写明豁免项、理由、影响面与到期复查日期，
不得跳过检查。到期后必须重新评审并处理结果。

## 与文档门禁的关系

`pnpm check:docs`（`scripts/check-docs.mjs`）覆盖的机器可判定项：

- `LICENSE` 是否为未改动的 GPL-2.0 原文（sha256）；
- `package.json` 与全部 workspace 成员的许可证字段是否都是 `GPL-2.0-only`；
- `deny.toml` 的 `[licenses]` allow 是否都落在已评审集合内，且含 `GPL-2.0-only`；
- 根目录治理文件是否齐备、`NOTICE` 四要素是否完整；
- `docs/**/*.md` 是否全部登记在 `docs/README.md`，相对链接是否可达；
- 治理文档元数据与评审记录命名/字段是否合规；
- 全文是否含过程痕迹标记。

门禁管不到、需要人工判断的：事实是否与代码一致、许可证义务是否被真正履行、
对外表述是否越权、外部条款是否变化。这些是清单存在的理由。

## 记录失效时怎么办

代码是唯一权威。若文档与代码冲突：立即以代码为准修文档，并在同一次记录里登记该偏差；
若偏差指向代码缺陷（如许可证字段不一致、缺少许可文本打包），单独开 issue 跟踪，
不在文档里长期挂"以文档为准"的空话。
